# 26B-013 测试订单与相机问题诊断

## 结论

Gitee `feature/ui-polish-camera` 已包含订单种子、订单物料需求模型和 CameraX 实现，但当前版本仍不能保证用户通过扫描测试订单进入订单详情。

## 已确认问题

### 1. 测试订单扫码类型不匹配

测试订单号为 `26B-013`，但后端扫码解析仍按旧规则只将 `SO` 或 `PO` 前缀识别为订单。`26B-013` 不满足该条件，会返回 `UNKNOWN`，Android ViewModel 随后不会调用订单查询。

修复要求：

- `/api/v1/scan/resolve` 必须把合法生产订单号 `26B-013` 识别为 `PRODUCTION_ORDER`。
- 生产订单号识别应以数据库中的 `production_orders.order_no` 精确查询为准，不要只依赖前缀猜测。
- 兼容契约允许的订单类型名称；客户端、后端统一使用 `PRODUCTION_ORDER`，不得混用 `ORDER_NO`、`LOGISTICS_NO`。
- 未命中的订单号返回 `UNKNOWN` 或明确的订单不存在错误，不能把全量物料当成订单结果。

建议函数签名：

```python
def resolve_scan(body: Scan, user: sqlite3.Row = Depends(current_user)) -> dict[str, Any]:
    ...
```

判定顺序：物料编码、生产订单号精确查询、流转单号、库位编码、UNKNOWN。查询连接必须关闭；只返回 `type`、`normalizedValue`、`resourceId` 等脱敏字段。

### 2. 订单查询必须按订单号过滤

`POST /api/v1/orders/material-status` 必须读取：

```text
production_orders
  -> order_material_requirements
  -> materials
  -> order_devices（可选但测试订单需要）
```

不能只查询 `materials` 全表。订单不存在返回 HTTP 404 和稳定错误码 `ORDER_NOT_FOUND`。

### 3. CameraX 调用必须有真实预览闭环

当前分支已有：

- `CAMERA` 运行时权限请求
- CameraX `Preview` 和 `ImageAnalysis`
- ML Kit 条码识别
- `STRATEGY_KEEP_ONLY_LATEST`
- 页面退出解绑相机
- 手动输入降级

需要重点验证以下闭环：

```text
ScannerScreen
  -> AndroidView/PreviewView
  -> ScannerViewModel.startScanning
  -> CameraXScannerRepository.startCamera
  -> ProcessCameraProvider.bindToLifecycle
  -> Preview.setSurfaceProvider
  -> ImageAnalysis analyzer
  -> ScanEvent
  -> resolveScan
  -> PRODUCTION_ORDER
  -> loadOrder("26B-013")
  -> OrderDetailScreen
```

当前实现中，`CameraPreviewPanel` 的 `AndroidView` factory 是相机启动的触发点。必须确保：

- `PreviewView` 真正加入 Compose 布局，不只是创建后立即移除。
- 只有 `CAMERA` 权限通过后才创建并绑定 `PreviewView`。
- `startScanning` 只启动一次，重试时先 `unbindAll`、关闭 analyzer 和 executor，再创建新的预览。
- `ImageProxy` 每条路径都调用 `close()`。
- 页面离开后不再收到扫码事件。
- CameraX 初始化失败时显示具体原因并保留手动输入。
- 真机或模拟器验证预览出图；单元测试不能替代相机硬件验证。

## 环境验证阻塞

本地后端测试收集失败于缺少 `fastapi` 依赖，未执行测试断言；不能把该结果报告为通过。应在项目虚拟环境安装 `material-flow-backend/requirements.txt` 后运行：

```bash
pytest material-flow-backend/tests -q
```

Android 需要在安装 Android SDK/JDK 的环境运行：

```bash
cd logistics-android
./gradlew --no-daemon :app:assembleDebug
```

必须区分：构建通过、模拟器运行、真机相机验证是三个独立证据。
