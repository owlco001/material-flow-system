# V1 状态与状态映射规范

## 1. 原则

库存、订单需求、出库流程、交接和工作台展示是五个不同状态域。API 必须返回状态域和服务端展示字段，客户端不得通过数量猜测核心业务状态。

## 2. 状态定义

- 库存域：`OUT_OF_STOCK`（缺货）、`ARRIVED`（到货）、`IN_STOCK`（在库）。
- 出库域：`OUTBOUND_PENDING`（待出库）、`OUTBOUND_APPROVED`（已审批）、`OUTBOUND_CONFIRMED`（已出库）。
- 交接域：`PENDING`、`CONFIRMED`、`REJECTED`、`CANCELLED`。
- 工作台域：`PICKED_UP`（已领取）、`AT_STATION`（已到机台）。

## 3. 合法转换

```text
OUT_OF_STOCK -> ARRIVED -> IN_STOCK
IN_STOCK -> OUTBOUND_PENDING -> OUTBOUND_APPROVED -> OUTBOUND_CONFIRMED
OUTBOUND_CONFIRMED -> PENDING -> CONFIRMED
PENDING -> REJECTED
PENDING -> CANCELLED
CONFIRMED / REJECTED / CANCELLED 为终态
```

`AT_STATION` 只能在交接确认且目标 `deviceId` 为订单关联机台时产生；`PICKED_UP` 只能在领取事件成功后产生。

## 4. 不变量

- 每条交接 `quantity > 0`；盘点允许 `actualQuantity >= 0`，两者不能混用。
- `0 <= pickedQuantity <= issuedQuantity <= requiredQuantity`。
- 出库确认前库存不扣减；出库确认和交接确认的关联操作必须按审批规则执行。
- 同一工作项存在 `PENDING` 交接时，不得创建重叠数量的第二条交接。
- 所有数量变化必须关联流转单/交接记录和审计事件。

## 5. API 字段要求

状态响应至少包含：`statusCode`、`statusLabel`、`colorToken`、`updatedAt`。工作台物料项还需包含 `lastHandoverId`、`currentOwnerUserId`、`currentOwnerName`。

未知 `colorToken` 使用安全中性色，但必须保留服务端 `statusLabel`；未知 `statusCode` 不得被映射为成功状态。

## 6. 验收

必须覆盖缺货→到货→在库、出库审批前后、交接确认/驳回/取消、重复交接、部分数量、并发版本冲突、退料和异常库存调整。
