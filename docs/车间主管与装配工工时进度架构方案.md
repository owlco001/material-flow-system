# 车间主管与装配工工时进度架构方案

## 1. 目标与范围

新增两个正式业务角色，并将装配执行过程纳入服务端事实链路：

- `WORKSHOP_SUPERVISOR`（车间主管）：查看所负责范围的工时统计、机台进度、订单总进度和异常，不直接代替装配工记录工时。
- `ASSEMBLER`（装配工）：接受已到位物料、开始装配、提交阶段进度 `1/2/3`、完工并记录本次工时。

临时调拨属于独立工作记录：装配工从当前装配任务临时转去处理其他工作时，必须结束或暂停当前计时，创建独立临时调拨工时记录，填写备注；临时工作时长不计入原装配任务工时，也不覆盖原任务进度。

本轮不引入薪资、绩效、考勤、自动排班或外部项目管理；工时仅服务于厂内生产进度统计。

## 2. 角色与权限

正式角色值：

- `WORKSHOP_SUPERVISOR`
- `ASSEMBLER`

既有角色继续保留：`OPERATOR`、`MATERIAL`、`WAREHOUSE_ADMIN`、`ADMIN`。

权限规则：

- `ASSEMBLER` 只能操作本人被分配的装配任务。
- `WORKSHOP_SUPERVISOR` 只能查看服务端授权车间/机台范围，可查看统计和明细，不可伪造装配工动作。
- `ADMIN` 可查看全量，并可在测试预览中只读查看新增两类工作台；预览不能执行写操作。
- 物料接受必须基于已存在且状态合法的物料交接/工作项，不能由客户端凭数量推导。
- 所有状态变更、计时开始/结束、进度提交和临时调拨均由服务端校验并写入审计。

## 4. 状态机

### 4.1 装配任务状态

```text
WAITING_MATERIAL
  -> MATERIAL_ACCEPTED
  -> IN_PROGRESS
  -> PAUSED_FOR_TEMPORARY_TRANSFER
  -> IN_PROGRESS
  -> COMPLETED
```

允许的补充路径：

- `MATERIAL_ACCEPTED -> CANCELLED`：仅服务端管理员/主管按业务规则执行，本轮客户端不提供取消。
- `IN_PROGRESS -> COMPLETED`：必须存在有效开始记录，完工时自动结束当前计时。
- `COMPLETED` 为终态，不允许再次开工、回退进度或追加原任务工时。

### 4.2 进度阶段

固定阶段：`1`、`2`、`3`。

- 只能按 `1 -> 2 -> 3` 顺序提交。
- 阶段提交必须携带服务端任务版本，版本冲突返回 `409 TASK_VERSION_CONFLICT`。
- `3` 不等于完工；完工仍需显式调用完成接口并记录工时。

### 4.3 临时调拨

```text
NONE -> TEMPORARY_TRANSFER_ACTIVE -> TEMPORARY_TRANSFER_COMPLETED
```

创建临时调拨时：

1. 若原装配任务正在计时，服务端原子结束该计时并将任务置为 `PAUSED_FOR_TEMPORARY_TRANSFER`。
2. 创建独立临时调拨记录，状态为 `ACTIVE`，开始时间由服务端生成。
3. 完成临时调拨时填写备注（1~500 字符），服务端结束临时记录。
4. 当前后端完成接口结束临时记录后，原任务保持服务端返回的 `PAUSED_FOR_TEMPORARY_TRANSFER`，Android 刷新后提供显式“继续开工”；临时调拨分钟数永不并入原装配任务。

### 5.2 REST API

所有写接口必须携带：`Authorization`、`X-Request-Id`、`Idempotency-Key`，且 body 中 `clientOperationId` 与 `Idempotency-Key` 相同。重复同 payload 返回原结果，不同 payload 返回 `409 IDEMPOTENCY_PAYLOAD_MISMATCH`。

#### 装配工任务

```http
GET /api/v1/assembly/tasks?page=1&pageSize=20
POST /api/v1/assembly/tasks/{taskId}/accept-material
POST /api/v1/assembly/tasks/{taskId}/start
POST /api/v1/assembly/tasks/{taskId}/progress
POST /api/v1/assembly/tasks/{taskId}/complete
```

请求体：

```json
{"clientOperationId":"uuid","expectedVersion":3}
```

进度接口额外字段：`{"stage":1|2|3}`。

真实 `assembly_routes.py` 响应形状：任务列表包含 `items/page/pageSize/total/totalPages`；接受物料、进度和完工返回任务状态/最新版本；开工返回 `laborRecordId/type/status/startedAt/taskVersion/serverTime`。服务端没有返回的 `materialSummary`、累计分钟数和机台工时等字段，客户端必须保持不可用，不能自行推导。

#### 临时调拨

```http
POST /api/v1/assembly/temporary-transfers/start
POST /api/v1/assembly/temporary-transfers/{transferId}/complete
```

开始请求：

```json
{"taskId":"string|null","remark":"string","clientOperationId":"uuid"}
```

完成请求：

```json
{"remark":"string","clientOperationId":"uuid"}
```

备注必填，长度 1~500。无当前任务时 `taskId=null` 允许建立独立临时工作记录，但必须归属当前装配工。

#### 车间主管统计

```http
GET /api/v1/workshop/summary
GET /api/v1/workshop/machine-progress?page=1&pageSize=20
```

统计口径：

- 当前后端按 `round(sum(progressStage) * 100 / (totalTasks * 3))` 返回 `overallProgressPercent`；无任务时为 `0`。客户端展示服务端值，不重新计算。
- `totalLaborMinutes = assemblyLaborMinutes + temporaryTransferLaborMinutes`。
- 机台进度由独立的分页接口返回；客户端不从任务列表计算机台或订单总进度。
- 当前统计接口不接受 `from/to` 查询参数，统计返回服务端已完成工时汇总；正在计时记录不计入分钟汇总。

错误码：

- `403 ASSEMBLY_TASK_FORBIDDEN`
- `409 ASSEMBLY_TASK_STATE_CONFLICT`
- `409 TASK_VERSION_CONFLICT`
- `409 PROGRESS_ORDER_CONFLICT`
- `409 ACTIVE_TRANSFER_EXISTS`
- `400 IDEMPOTENCY_KEY_MISMATCH`
- `422 VALIDATION_ERROR`（备注为空或超出 500 字符）

当前后端以 `clientOperationId` 查询 `assembly_operations`/`temporary_transfers` 并返回原结果；装配路由没有额外保存并比较请求 payload，因此 Android 不宣称服务端提供未实现的 `IDEMPOTENCY_PAYLOAD_MISMATCH`。

## 6. 数据结构定义

### 6.1 `assembly_tasks`

- `id TEXT PRIMARY KEY`
- `order_no TEXT NOT NULL`
- `device_id TEXT NOT NULL`
- `device_no TEXT NOT NULL`
- `assigned_assembler_id TEXT NULL REFERENCES users(id)`
- `status TEXT NOT NULL`
- `progress_stage INTEGER NOT NULL DEFAULT 0 CHECK(progress_stage BETWEEN 0 AND 3)`
- `task_version INTEGER NOT NULL DEFAULT 1`
- `material_accepted_at TEXT NULL`
- `completed_at TEXT NULL`
- `created_at TEXT NOT NULL`
- `updated_at TEXT NOT NULL`

唯一约束：`(order_no, device_id, assigned_assembler_id, id)`；任务 ID 是业务主键。

### 6.2 `labor_records`

- `id TEXT PRIMARY KEY`
- `task_id TEXT NULL REFERENCES assembly_tasks(id)`
- `worker_user_id TEXT NOT NULL REFERENCES users(id)`
- `type TEXT NOT NULL CHECK(type IN ('ASSEMBLY','TEMPORARY_TRANSFER'))`
- `status TEXT NOT NULL CHECK(status IN ('ACTIVE','COMPLETED'))`
- `started_at TEXT NOT NULL`
- `ended_at TEXT NULL`
- `duration_minutes INTEGER NULL CHECK(duration_minutes IS NULL OR duration_minutes >= 0)`
- `remark TEXT NULL`
- `client_operation_id TEXT NOT NULL UNIQUE`
- `created_at TEXT NOT NULL`

约束：同一 `worker_user_id` 同时最多一条 `ACTIVE` 记录；`TEMPORARY_TRANSFER` 不得与 `task_id` 为空时缺少 remark。

### 6.3 `progress_events`

- `id TEXT PRIMARY KEY`
- `task_id TEXT NOT NULL REFERENCES assembly_tasks(id)`
- `worker_user_id TEXT NOT NULL REFERENCES users(id)`
- `from_stage INTEGER NOT NULL`
- `to_stage INTEGER NOT NULL CHECK(to_stage BETWEEN 1 AND 3)`
- `task_version INTEGER NOT NULL`
- `server_time TEXT NOT NULL`
- `client_operation_id TEXT NOT NULL UNIQUE`

### 6.4 `temporary_transfers`

- `id TEXT PRIMARY KEY`
- `worker_user_id TEXT NOT NULL REFERENCES users(id)`
- `source_task_id TEXT NULL REFERENCES assembly_tasks(id)`
- `labor_record_id TEXT NOT NULL UNIQUE REFERENCES labor_records(id)`
- `status TEXT NOT NULL CHECK(status IN ('ACTIVE','COMPLETED'))`
- `remark TEXT NOT NULL CHECK(length(remark) BETWEEN 1 AND 500)`
- `started_at TEXT NOT NULL`
- `ended_at TEXT NULL`
- `client_operation_id TEXT NOT NULL UNIQUE`

### 6.5 审计

复用 `audit_events`，新增事件：

- `MATERIAL_ACCEPTED_FOR_ASSEMBLY`
- `ASSEMBLY_STARTED`
- `ASSEMBLY_PROGRESS_UPDATED`
- `ASSEMBLY_COMPLETED`
- `TEMPORARY_TRANSFER_STARTED`
- `TEMPORARY_TRANSFER_COMPLETED`

审计必须记录真实操作者、角色、任务/调拨 ID、requestId、clientOperationId、服务端时间、前后状态；不得记录 Token、密码或 source_ip。

## 7. 技术选型及理由

- Android 继续使用 Compose + ViewModel + Repository，新增角色和状态枚举集中定义，避免 UI 字符串驱动权限。
- 服务端继续使用 FastAPI + SQLite 兼容模型，所有状态与工时变更采用单事务；生产并发增长时可平滑迁移 PostgreSQL。
- 服务端时间作为工时事实，客户端仅显示本地运行计时，断网不允许提交需要精确结束时间的完工动作。
- 工时按分钟统计，`durationMinutes = floor((endedAt - startedAt) / 60 seconds)`；不足 1 分钟计 `0`，原始时间仍保留。
- 8GB Android 设备只加载 20 条任务/机台，统计由服务端聚合，客户端不拉全量任务计算总进度。
- 临时调拨采用独立实体而非给原任务增加备注，确保主管能分别查看装配工时和临时工作工时。

## 8. 验收标准

1. 六种正式角色值可被服务端和 Android 正确解析；旧角色权限不扩大。
2. 装配工只能看到本人任务，能按合法顺序完成接受物料、开工、进度 1/2/3、完工。
3. 开工生成服务端计时记录；完工生成结束时间和分钟数，重复请求不重复计时。
4. 车间主管能看到工时总计、装配工时、临时调拨工时、机台进度和订单总进度。
5. 临时调拨有独立计时记录和必填备注，时长不计入原装配任务工时。
6. 同一时刻同一装配工不能有两个 ACTIVE 工时记录。
7. 越权、状态冲突、版本冲突、进度越级和幂等冲突均返回明确错误码。
8. 每个业务动作都有脱敏审计事件和服务端时间。
9. 管理员测试角色预览可查看新增工作台，但保持只读且不改变真实 ADMIN 身份。
10. 8GB 中端 Android 分页加载稳定；后端测试、Android JVM 单测、Debug 构建和真实测试环境接口验证分别通过。

### Android order-detail refresh gap
Android now refreshes the existing POST /api/v1/orders/material-status response after successful role mutations. A dedicated order detail endpoint carrying assembly/labor/timeline facts does not exist in the inspected backend contract; those fields remain unavailable until the backend agent defines and ships a contract.
