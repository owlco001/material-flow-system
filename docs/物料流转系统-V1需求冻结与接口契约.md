# 物料流转系统 V1 需求冻结与接口契约

## 1. 需求确认

本文件根据已确认业务规则冻结 V1 设计；未列出的细节按本文默认值执行。

- 物料编码：包含批次/规格/有效期等扩展维度，当前 V1 支持扩展字段。
- 扫码对象：生产订单号、料号、库位码、厂内流转单号、异常凭证。
- 生产订单号：扫码提交后返回该生产订单当前物料状态及厂内流转状态。
- 物料状态：红=缺货，黄=到货，绿=在库。接口同时返回枚举值和展示颜色，客户端不得只依赖颜色。
- 料号：扫码后返回库存及物料详情。
- 数量：V1 仅允许正整数，不允许小数。
- 库存：不允许负库存；出库/调拨发出前必须校验可用库存。
- 审批：入库和出库必须审批；调拨、盘点、库位绑定、异常提报按简化流程执行，异常除外。
- 用户角色：管理员、仓库管理员、物料员、操作员。
- 访问范围：暂时公网，通过 HTTPS 访问；后续可增加公司 VPN/IP 白名单。
- 初始管理员账号：`owlco`。初始密码不得写入文档、代码或数据库明文，首次登录必须改密。
- 审计：所有用户操作记录服务端时间戳、操作者、角色、IP、设备 ID、请求 ID和前后状态。
- 图片：物料流转允许上传库位图片、异常图片等凭证；图片与业务单据绑定。

## 2. 状态规则

### 2.1 单据物料状态

| 枚举 | 含义 | 展示语义 | 颜色 | 进入条件 |
|---|---|---|---|---|
| `OUT_OF_STOCK` | 缺货 | 缺货 | 红 | 可用库存小于需求量，或订单未到货 |
| `ARRIVED` | 到货 | 到货 | 黄 | 已收货但尚未完成入库确认 |
| `IN_STOCK` | 在库 | 在库 | 绿 | 已完成入库且存在可用库存 |

状态颜色固定为：红 `#D92D20`、黄 `#F2A900`、绿 `#1F9D55`。接口必须返回 `statusCode`、`label`、`colorToken`，客户端还必须展示图标和文字。

### 2.2 入库/出库审批

```text
DRAFT → SUBMITTED → PENDING_APPROVAL → APPROVED → EXECUTED
                              └──────────────→ REJECTED
```

- 操作员/物料员可创建并提交申请。
- 仓库管理员可审核入库、出库。
- 管理员拥有全部审批权限。
- 主管角色不纳入 V1；如后续需要，新增角色不改变审批接口。
- 审批通过后才允许实际变更库存。
- 审批拒绝必须填写原因。
- 审批和执行必须记录不同的用户与时间戳；同一用户默认不得既审批又执行同一单据。

### 2.3 简化流程

- 调拨：提交后直接执行，但必须校验库存和目标库位。
- 盘点：物料员录入实盘数量，仓库管理员确认差异；不允许直接造成负库存。
- 库位绑定：扫码物料码 + 库位码后直接保存，记录图片可选。
- 异常：创建异常单，上传图片可选；涉及库存调整时转审批。

## 3. 扫码解析规则

扫码结果必须先识别类型，再调用对应接口：

- `PRODUCTION_ORDER`：生产订单号
- `FLOW_NO`：厂内流转单号
- `MATERIAL_CODE`：料号
- `LOCATION_CODE`：库位码
- `UNKNOWN`：无法识别，提示手动输入或重新扫码

首版采用前缀+正则配置，不把规则硬编码到 UI。服务端下发规则配置；未命中时客户端调用 `POST /api/v1/scan/resolve` 由服务端最终判定。

## 4. API 契约

Base URL：生产环境通过 HTTPS 配置；客户端不得硬编码 IP。

### 4.1 登录

`POST /api/v1/auth/login`

请求：

```json
{
  "username": "owlco",
  "password": "<客户端提交，不写入日志>",
  "deviceId": "uuid",
  "clientVersion": "0.2.0"
}
```

响应：

```json
{
  "accessToken": "jwt",
  "refreshToken": "opaque-token",
  "expiresAt": "2026-09-12T12:00:00Z",
  "mustChangePassword": true,
  "user": { "id": "u_001", "username": "owlco", "displayName": "管理员", "role": "ADMIN" }
}
```

规则：密码使用 Argon2id 哈希；refresh token 仅存服务端哈希；登录、刷新、退出均写审计日志；连续 5 次失败锁定 15 分钟。

### 4.2 扫码解析

`POST /api/v1/scan/resolve`

```json
{ "rawValue": "SO202609120001", "clientOperationId": "uuid" }
```

```json
{
  "type": "ORDER_NO",
  "normalizedValue": "SO202609120001",
  "resourceId": "ord_001"
}
```

### 4.3 生产订单物料状态

`POST /api/v1/orders/material-status`

请求：

```json
{
  "documentType": "ORDER_NO",
  "documentNo": "SO202609120001"
}
```

响应：

```json
{
  "documentNo": "SO202609120001",
  "documentType": "ORDER_NO",
  "items": [
    {
      "materialId": "mat_001",
      "materialCode": "MTR-001",
      "name": "工业轴承",
      "requiredQuantity": 10,
      "arrivedQuantity": 10,
      "inStockQuantity": 8,
      "statusCode": "IN_STOCK",
      "label": "在库",
      "colorToken": "status-green"
    }
  ],
  "serverTime": "2026-09-12T12:00:00Z"
}
```

生产订单详情同时返回该订单的物料状态和厂内流转记录；不返回外部运输、承运商或物流轨迹信息。

### 4.4 料号库存

`GET /api/v1/materials/{materialCode}/inventory`

响应：

```json
{
  "material": {
    "id": "mat_001",
    "code": "MTR-001",
    "name": "工业轴承",
    "specification": "6205-2RS",
    "unit": "件",
    "batchNo": "B20260912",
    "expiryDate": null
  },
  "inventory": {
    "totalQuantity": 986,
    "availableQuantity": 986,
    "reservedQuantity": 0,
    "locations": [
      { "locationCode": "A-01-03", "quantity": 986 }
    ]
  },
  "version": 12
}
```

### 4.5 入库/出库申请

`POST /api/v1/transfer-requests`

请求：

```json
{
  "clientOperationId": "uuid",
  "type": "INBOUND",
  "documentNo": "SO202609120001",
  "items": [
    {
      "materialId": "mat_001",
      "quantity": 10,
      "batchNo": "B20260912",
      "targetLocationCode": "A-01-03",
      "expectedInventoryVersion": 12
    }
  ],
  "remark": "正常入库",
  "evidenceIds": ["file_001"]
}
```

响应返回：`requestId`、`status=PENDING_APPROVAL`、服务端时间戳、审计 traceId。

`POST /api/v1/transfer-requests/{requestId}/approve`

```json
{ "decision": "APPROVE", "comment": "数量与单据一致" }
```

`POST /api/v1/transfer-requests/{requestId}/execute`

仅允许审批通过后执行；服务端事务内校验库存版本和不可负库存约束。

### 4.6 调拨、盘点、库位绑定

- `POST /api/v1/relocations`：调拨，要求来源库存和版本号，成功后同时扣减来源、增加目标。
- `POST /api/v1/stocktakes`：盘点，数量为正整数或 0，差异由仓库管理员确认。
- `POST /api/v1/location-bindings`：请求包含 `materialCode`、`locationCode`、`quantity`、可选 `evidenceIds`。

### 4.7 图片上传

`POST /api/v1/files`，`multipart/form-data`

字段：`file`、`purpose`（`LOCATION` / `EXCEPTION` / `TRANSFER`）、`sha256`。

限制：JPEG/PNG/WebP；单张不超过 5MB；最长边服务端压缩为 1920px；单业务单据最多 9 张；文件落盘使用随机 ID，不使用原始文件名；上传成功返回 `fileId`、宽高、大小、sha256。

### 4.8 审计日志

`GET /api/v1/audit-logs?page=1&pageSize=50&operatorId=&action=&from=&to=`

审计记录字段：`id`、`operatorId`、`role`、`action`、`resourceType`、`resourceId`、`requestId`、`ip`、`deviceId`、`occurredAt`、`beforeJson`、`afterJson`、`result`。

## 5. 统一约束

- 数量 JSON 使用整数；服务端拒绝小数、负数、超大整数和科学计数法。
- 所有写操作需要 `Authorization: Bearer`、`Idempotency-Key` 和 `X-Request-Id`。
- 幂等键保存至少 7 天；同一键不同 payload 返回 `IDEMPOTENCY_PAYLOAD_MISMATCH`。
- 库存写操作必须在数据库事务中完成。
- 服务端时间为审计和业务时间唯一依据；客户端时间仅作为展示参考。
- 错误结构：`code`、`message`、`traceId`、`retryable`、`details`。
- 不允许把密码、token、图片内容写入日志。
