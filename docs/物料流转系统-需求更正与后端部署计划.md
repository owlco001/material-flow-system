# 物料流转系统更正与后端部署计划

## 需求更正

- 正确名称：**物料流转系统**
- 使用范围：公司内部
- 目标终端：Android APP
- 后端部署位置：已加固的 VPS `107.173.70.115`
- 当前 VPS：Ubuntu 24.04，约 1GB RAM、23GB 磁盘；当前仅 SSH 监听公网，未发现 Docker、Nginx、PostgreSQL 等现有应用服务

## 纠正内容

之前文档中的“物流流转”统一视为命名错误；业务对象应使用“物料”。本系统关注公司内部物料的收货、入库、出库、调拨、盘点、库位绑定、异常审批和操作审计。

Android 包名、页面标题、接口资源名和数据库表名应采用 `material` / `materials` / `material_transfer`，不得继续使用 `logistics` 作为业务名称。

## 推荐后端部署方案

考虑 VPS 只有约 1GB RAM，不建议直接部署重量级 Kubernetes、Java 全家桶或同时运行多个数据库。第一阶段采用：

```text
Internet / Company Network
        │ HTTPS :443
        ▼
Nginx/Caddy reverse proxy
        │ localhost:8000
        ▼
FastAPI backend (Python)
        │
        ├── SQLite WAL（第一阶段内部低并发）
        └── 本地文件存储（异常凭证，限制大小）
```

如果公司并发超过约 20 个活跃用户、需要高可用或已有 PostgreSQL，则将数据库替换为 PostgreSQL；API 层保持不变。

## 第一阶段后端功能

- 账号登录、角色和权限
- 物料主数据
- 库位主数据
- 入库、出库、调拨、盘点
- 库位绑定
- 离线 APP 操作幂等提交
- 库存版本冲突
- 异常单和主管审批
- 审计日志
- 健康检查和备份

## 必须冻结的业务规则

- 物料编码是否唯一、是否包含批次和规格
- 数量单位：件、箱、公斤等是否允许小数
- 库存是否按批次、供应商、有效期拆分
- 出库是否允许负库存
- 调拨是否需要审批
- 盘点差异的审批阈值
- 物料和库位条码格式
- 公司内部用户的登录方式（账号密码、企业微信、LDAP 或其他）
- APP 是否只能在公司网络/VPN访问

## 安全建议

- 后端不直接开放 8000，仅绑定 `127.0.0.1`
- 公网仅开放 22；正式接入 HTTPS 前不开放 80/443
- APP 通过 HTTPS 访问，生产禁用明文 HTTP
- root 密码已暴露，必须在控制台重置；应用密钥不能复用 SSH 凭据
- 每个流转请求携带 `clientOperationId`，服务端唯一约束保证重试不重复扣库存
- 库存更新使用事务和 `version` 乐观锁
- 每次库存变更写入不可变审计记录
- 每日 SQLite 备份，保留 14 天，备份文件不得直接暴露公网
