# V1 角色与枚举契约冻结决议

## 1. 决议优先级

本文件作为角色化工作台迭代的补充冻结文件，优先级高于早期示例；后续源码、测试、Android 解析器和 API 文档必须按本文件统一。

## 2. 唯一枚举

### 2.1 用户角色

服务端协议值固定为：

- `OPERATOR`：操作员
- `MATERIAL`：物料员
- `WAREHOUSE_ADMIN`：仓库管理员
- `ADMIN`：管理员

`MATERIAL_CLERK` 不再作为新请求或新数据库值。历史数据迁移时允许一次性映射为 `MATERIAL`，客户端不得自行把两个值当作长期兼容分支。

### 2.2 订单查询类型

固定为 `PRODUCTION_ORDER`。`ORDER_NO` 为废弃值，新接口返回 `400 INVALID_DOCUMENT_TYPE`，不得继续作为成功兼容值。

### 2.3 扫码类型

固定为：`PRODUCTION_ORDER`、`MATERIAL_CODE`、`LOCATION_CODE`、`FLOW_NO`、`UNKNOWN`。`FLOW_RECORD` 为废弃文档值，统一改为 `FLOW_NO`。

### 2.4 业务状态分层

- 库存状态：`OUT_OF_STOCK`、`ARRIVED`、`IN_STOCK`
- 出库流程状态：`OUTBOUND_PENDING`、`OUTBOUND_APPROVED`、`OUTBOUND_CONFIRMED`
- 交接状态：`PENDING`、`CONFIRMED`、`REJECTED`、`CANCELLED`
- 操作员展示状态：`PICKED_UP`、`AT_STATION`

`PICKED_UP`、`AT_STATION` 不是库存状态，必须来自交接事件或工作项状态；客户端不得由 `arrivedQuantity` 或 `inStockQuantity` 自行推导。

## 3. 机台与禁用边界

“目标机台”表示生产订单中已登记的设备责任归属，不等于线边库、配送工位或工位实体。系统不建立 `station`、`line_side_warehouse`、`delivery_point` 等实体，也不使用“配送中”“运输中”等外部物流语义。

交接目标字段统一使用 `deviceId`，展示使用中文机台名和后端 `deviceNo`；不使用自由文本伪造目标位置。

## 4. 兼容与迁移

- API 新请求只接受冻结值；旧值只允许在明确的数据库迁移脚本中处理。
- Android `from(code)` 对未知角色/状态必须进入安全默认态并上报解析错误，不得将未知角色静默提升权限。
- 所有契约测试必须覆盖旧值拒绝、新值成功和错误结构。
