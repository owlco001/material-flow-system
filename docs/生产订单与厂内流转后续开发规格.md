# 生产订单与厂内流转后续开发规格

## 8. 技术栈与取舍理由

- **Android 客户端：Kotlin + Jetpack Compose + Room + WorkManager/Coroutines**
  - 只保留一套组件体系，降低维护面；Compose 有利于快速落地厂内场景的高可读界面。
  - Room + WorkManager 适配断网重试与“离线暂存再同步”能力。
  - Retrofit/OkHttp 建议在 `Network` 模块中替换当前轻量 HTTP 现实现有实现。
  - 理由：移动端当前目标为 Android，内存/算力约 8GB 设备，需控制体积与依赖，仍可保持可验证的离线能力。

- **后端：FastAPI + Pydantic + SQLite（PoC）/PostgreSQL（生产）**
  - FastAPI 与本仓库现有 `material-flow-backend/app/main.py` 一致，最小改动即可接入。
  - SQLite 作为 PoC 过渡数据库可快速启动，生产期建议迁移到 PostgreSQL 以支持事务并发与更好观测。
  - 理由：接口类型与字段语义（如 `PRODUCTION_ORDER`、`LOCATION_CODE`、`FLOW_RECORD`）可通过单点 schema 映射控制变更。

- **安全：HTTPS + Bearer Token + 请求 ID + 幂等键**
  - `ApiConfig` 与 `MaterialFlowApi`（客户端）与服务端统一要求 `Authorization`/`Idempotency-Key`/`X-Request-Id`。
  - 理由：离线重放场景必须可追溯、可去重；审计场景必须可回溯到操作人/请求与服务端时间。

- **可观测：日志、审计和冲突码归档**
  - 统一写入 `AuditLog`（含操作者、角色、IP、设备、请求ID、状态变更前后）。
  - 理由：后续生产追责与回溯必须满足库存变更可追踪。

## 9. 接口与数据一致性约束（简表）

| 模块 | 约束 | 风险 | 校验点 |
|---|---|---|---|
| 扫码解析 | 文本类型仅支持 `PRODUCTION_ORDER`/`MATERIAL_CODE`/`LOCATION_CODE`/`FLOW_RECORD`/`UNKNOWN` | 遗留 `LOGISTICS_NO`/`ORDER_NO` 残留 | 订单查询与后端 `/api/v1/scan/resolve` 返回类型对齐 |
| 流转申请 | 数量、乐观锁、版本冲突必须在服务端拒绝 | 负库存/超配、并发丢失 | `expectedInventoryVersion`、事务边界测试 |
| 离线队列 | 幂等键可重放且不可重复创建 | 重复提交引发重复单据 | `Idempotency-Key` 去重计数与重放状态 |
| 审批执行 | `PENDING_APPROVAL` 前不可执行 | 越权执行/状态回退 | 状态机和角色鉴权单测 |
| 术语清洗 | 禁止外部物流字段/文案 | 需求漂移 | 术语审计脚本扫描 `docs` 与运行时文案 |

## 1. 范围

本规格用于 `feat/ui-fusion` 合并后的后续开发。系统只处理公司内部生产订单和厂内物料流转，不处理外部物流、承运商、运输轨迹、线边库或配送工位。

## 5. 事务与权限

- `INBOUND`、`OUTBOUND`：创建申请后必须审批；审批前不得修改库存。
- `RELOCATION`：单数据库事务内锁定来源库存行，校验版本和数量，再扣减来源并增加目标。
- `RETURN`：作为入库方向的独立流转记录，按入库审批规则处理。
- `STOCKTAKE`：提交实盘数量，仓库管理员确认差异。
- `ADJUSTMENT`：涉及库存变化时必须审批。
- 操作员可提交申请；物料员可提交申请和盘点；仓库管理员可审批和确认；管理员拥有全部权限。
- 同一用户不得审批并执行同一申请。
- 所有写接口必须接收 `Authorization` 和 `X-Request-Id`，服务端写入 UTC 时间。

5. 最后补齐图片、离线持久化、WorkManager 和自动化测试。
