# V1 审计与留痕字段规范

## 1. 两类日志关系

- `audit_logs`：兼容现有认证、流转申请和系统操作记录。
- `audit_events`：交接和物料状态领域的只追加事实事件；新交接功能必须写入此表，不能把字段硬塞入窄审计表。

## 2. `audit_events` 必填字段

```text
id, event_type, entity_type, entity_id,
actor_user_id, actor_role, request_id,
client_operation_id, before_json, after_json,
server_time, device_id, source_ip, result
```

`client_operation_id` 对非幂等读事件可为空；交接创建、确认、驳回、取消必须非空。`before_json/after_json` 只保存业务状态摘要，不保存密码、token、身份证件、完整请求头或支付信息。

## 3. 事件枚举

`HANDOVER_CREATED`、`OUTBOUND_APPROVED`、`OUTBOUND_CONFIRMED`、`HANDOVER_CONFIRMED`、`HANDOVER_REJECTED`、`HANDOVER_CANCELLED`、`MATERIAL_PICKED_UP`、`MATERIAL_AT_STATION`。

## 4. 写入规则

- 事件与业务变更同事务提交。
- 事件只追加，不允许 UPDATE/DELETE；纠错使用反向补偿事件。
- 服务端生成 `server_time`，客户端时间只能作为可选展示字段。
- `source_ip` 由服务端从连接获取；设备 ID 来自已认证会话，不信任任意 body 覆盖。
- 查询权限：普通角色只能查询自己业务范围；仓库管理员查询仓库范围；管理员查询全量。

## 5. 验收

每个事件必须能回放出操作者、角色、设备、请求、幂等键、前后状态、服务端时间和结果；日志中不得出现密码、refresh token 或 access token。
