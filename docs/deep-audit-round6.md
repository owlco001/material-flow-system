# 第六轮：多Agent并发开发机台流转范围与分区加载

基线815b4a9；工作分支fix-deep-audit-138ff95。三路并发写入互不重叠，Lead统一跨层接口、版本、构建和最终验收。本轮版本后端0.22.4、Android0.5.57 / 64；不推送、不部署、不发布APK，不访问测试服务器。

## 开发范围及接口约定

- 服务端路：GET /api/v1/transfer-requests新增重复documentNo query精确筛选；权限、status与订单范围共同约束count和items。无筛选时兼容原接口及管理台内部调用。最多100个去重非空订单编号，不以新增64字符限制误伤历史编号。
- Android传输路：新增transferRequestsForOrders(Set<String>)与listTransferRequestsForOrders(Set<String>)；每批20个订单编号、每页100条，空集不发HTTP。机台专用读取不能在5000条处静默成功，异常上限需明确失败。保留旧服务器忽略筛选后的防御过滤与身份/分页保护。
- Android页面路：任务、物料、流转、工时分区同父job并发，使用跨刷新共享Semaphore(4)，完成一块即显示一块。每次成功/失败/加载状态写回均校验session、请求世代、当前机台与路由；加载中不是空数据，某块失败不取消其他块。

## 协作方式

三名执行者分别持有main.py+后端新测试、API/Repository+传输新测试、ViewModel/页面+并发新测试的写范围；不互写、不各自提交。Android Gradle由Lead集中串行运行；后端局部测试与Android测试可并行。最初新增接口允许最小TDD委托桩以取得可编译行为红测，最终必须用完整实现替换，不留反射/兼容测试桥或临时生产分支。

## 验收证据

服务端两项初始行为红测复现了未识别documentNo导致全量回退和空白参数未拒绝；修复后Lead完整后端验收602 passed（302.81s）。覆盖权限不扩张、状态叠加、两页排序不重不漏、256字符历史编号、内部四参数调用及已有事务兼容。

Android类型安全最小TDD接口桩仅委托旧全量读取；最初11项中10红（范围接口5/6红，页面5/5红），随后两路集成38项及完整303项已通过。交叉复核补充4项行为红测：trim一致性、缺total时短页与totalPages矛盾、totalPages变化、返回已取消的机台残留LOADING。这些边界均已在本轮红转绿。最终冻结Android307项/54类，0失败/错误/跳过，包含范围读取15项和机台并发7项，原20项机台生命周期/完整分页测试未修改且全部通过。testDebugUnitTest与assembleDebug成功（最后一轮1m3s）。后端最终完整602项零失败；Room实际生成SQL、图标75文件、YAML/文件映射、全部ratchet及diff格式检查通过。

## 保留边界

不变更正式角色责任范围、不扩大订单可见性、不做库存小数或离线owner迁移。旧服务器忽略订单筛选时客户端可能仍需下载全量，正确性兼容不等于性能收益。机台专用新读取与既有全局审批/个人页的旧流转读取明确分开；不可把本轮机台修复说成所有列表已完成迁移。跨HTTP多页不是数据库事务快照，只能按元数据检测部分变化。真机、加密磁盘、后台调度、生产U9与远端CI仍需独立验收。
