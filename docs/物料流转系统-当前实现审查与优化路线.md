## 4. 必须修复的高优先级缺口

### P0-1：统一扫码和订单枚举

现状：后端仍可能返回 `MACHINE`，订单查询仍兼容 `ORDER_NO`。

目标：严格使用：

```text
PRODUCTION_ORDER
FLOW_NO
MATERIAL_CODE
LOCATION_CODE
UNKNOWN
```

禁止运行时出现 `MACHINE`、`ORDER_NO`、`LOGISTICS_NO` 等旧值。设备码如需支持，应通过现有业务类型映射为契约允许的资源表达，不新增未冻结枚举。

接口签名：

```python
POST /api/v1/scan/resolve(body: ScanResolveRequest) -> ScanResolveResponse
POST /api/v1/orders/material-status(body: OrderMaterialStatusRequest) -> OrderMaterialStatusResponse
```

验收：旧枚举返回 400；Android 和后端测试同时更新；真实 seed 条码可被解析。

### P0-2：补齐写接口结构化模型和请求头门禁

现状：库位绑定、盘点、异常和部分文件接口仍使用裸 `dict` 或不完整的请求头约束。

目标：每个写接口使用 Pydantic 请求模型，统一要求：

```http
X-Request-Id: UUID
Idempotency-Key: UUID（幂等写接口）
```

必须覆盖：库位绑定、盘点创建/确认、异常创建/审核、文件上传元数据、交接动作。

禁止通过客户端隐藏替代服务端鉴权；所有写入均需服务端角色校验、审计和幂等记录。

### P0-3：Android 离线同步改为可恢复状态机

现状：Room 已有离线记录，但 payload 未加密，`syncPending` 由协程逐条执行，没有 WorkManager 自动联网触发、批量上限、并发上限和进程重启恢复证据。

目标：

```text
QUEUED → SYNCING → SUCCEEDED
                 ├→ RETRY_WAIT（网络/5xx）
                 ├→ CONFLICT（409）
                 └→ FAILED（不可重试）
```

固定参数：

- 每批最多 20 条。
- 并发最多 2。
- 自动重试最多 5 次。
- `clientOperationId` 重试不变。
- 409 进入 `CONFLICT`，不得自动改写 payload。
- payload 使用 Android Keystore 派生密钥加密。
- Worker 使用网络约束，进程被杀后可从 Room 恢复。

### P0-4：完成扫码到业务闭环

目标链路：

```text
权限 → PreviewView → CameraX 绑定 → 条码分析
→ 服务端 resolve → PRODUCTION_ORDER
→ 订单详情 → 物料状态 → 流转申请
→ 审批/执行 → 审计
```

保留手动输入和扫码枪适配接口作为降级入口。不得仅以静态 CameraX 代码宣称扫码验收完成。

### P0-5：真机与部署验收

必须实际记录：

- 设备型号、Android 版本、内存档位。
- 首次相机授权、拒绝、永久拒绝、无相机。
- QR、Code 128、Data Matrix。
- 旋转、锁屏、后台恢复和 30 分钟连续扫码。
- 200% 字体、TalkBack、断网/弱网、进程被杀恢复。
- APK 路径、大小、SHA-256、aapt 元数据。
- 后端部署 revision、健康检查、只读业务接口、数据库备份和回滚结果。

## 5. 技术选型及理由

- Android 网络层：优先 Retrofit + OkHttp，减少手写 HTTP 状态和 JSON 解析错误；使用统一错误 DTO 保留 `code/retryable/traceId`。
- Android 序列化：kotlinx.serialization，DTO 与 JSON 字段显式绑定。
- 离线数据库：Room，采用迁移而不是破坏性重建；payload 使用 Keystore 加密后再落库。
- 调度：WorkManager，使用网络约束、唯一工作名和指数退避；业务幂等由服务端最终保证。
- 后端 API：FastAPI + Pydantic，写接口禁止裸 `dict`；保留 SQLite WAL 作为开发/测试实现，生产切换 PostgreSQL。
- 部署：systemd + Uvicorn + Nginx；生产必须 HTTPS，测试 HTTP 仅限受控网络。
- 测试：后端 pytest；Android JVM/Compose 契约测试；MockWebServer；真机专项测试单独记录，不以编译替代。

## 6. 模块依赖约束

```text
UI/Compose
  → ViewModel/StateFlow
    → UseCase/Domain policy
      → Repository interface
        → Retrofit/Room/WorkManager adapters

FastAPI routes
  → Pydantic request/response models
    → authorization/idempotency service
      → transaction service
        → SQLite/PostgreSQL repository
          → audit service
```

禁止：

- Composable 直接发 HTTP。
- 客户端根据数量推导领取/到工位/审批状态。
- 客户端绕过服务端角色判断。
- 业务代码依赖 APK 中的固定公网地址。
- seed 写入密码、Token、真实主机信息或可登录默认账号。

## 7. 风险与打回项

以下事项在修复前不能标记为完整 V1：

1. 后端继续返回契约外 `MACHINE` 或接受旧 `ORDER_NO`。
2. 写接口继续使用裸 `dict` 或缺少幂等/请求 ID。
3. 以当前协程同步实现宣称 WorkManager 离线能力。
4. 以 APK 构建成功宣称真机扫码和断网恢复通过。
5. 以 SQLite 测试部署宣称生产数据库部署完成。
6. 在现有已初始化 VPS 上隐式重置管理员密码或破坏 setup 状态。
