# 后端部署向导与初始管理员激活方案

## 1. 目标与边界

本方案将“后端部署”和“初始管理员设置”从人工猜测改为页面引导流程，适用于测试环境和后续内网环境。

安全边界：

- 页面只负责采集并提交初始管理员密码；密码不得写入 Git、普通日志、数据库明文、APK、URL、查询参数或聊天。
- 服务端只保存 Argon2id 密码哈希。
- 初始管理员首次登录后必须改密；未改密前不能访问业务接口、用户管理或订单数据。
- 部署页面不得展示或回显现有密码。
- 部署状态与业务数据初始化分离；重置测试数据不得重置系统管理员哈希，除非执行明确的管理员重置操作。
- 正式环境必须使用 HTTPS；测试环境的明文 HTTP 只能在受控内网/测试网使用。

## 2. 模块图（文字版）

```text
Android LoginScreen
  ├─ 后端未配置提示
  └─ 部署向导/服务端配置页
       ├─ 地址格式校验
       ├─ GET /healthz 连通性测试
       ├─ 部署状态查询（不含密码）
       └─ 初始管理员激活表单
            └─ POST /api/v1/setup/initialize-admin
                 ├─ 服务端一次性初始化锁
                 ├─ Argon2id 哈希
                 ├─ must_change_password = 1
                 ├─ 审计（不含密码）
                 └─ 返回 setup 状态

FastAPI
  ├─ SetupGuard（初始化状态与一次性锁）
  ├─ AdminActivationService（哈希/策略/审计）
  ├─ AuthService（登录/首次改密/会话）
  └─ Business API（首次改密前拒绝）
       └─ SQLite WAL / 后续 PostgreSQL
```

## 3. 页面与状态

### 3.1 未配置后端页面

显示：

- 当前状态：未配置后端
- 后端地址输入框
- “测试连通性”按钮
- “保存并继续”按钮
- HTTP 明文风险提示

行为：

- 地址必须为 `http://` 或 `https://` URL，不允许用户名、密码、Token、查询参数。
- 测试请求只访问 `/healthz`，不发送凭据。
- 保存地址后进入“初始管理员激活”页面。

### 3.2 初始管理员激活页面

字段：

- 管理员账号：服务端返回的固定账号名，仅展示，不允许客户端任意创建系统管理员。
- 初始密码：密码输入框，不回显。
- 确认初始密码：密码输入框，不回显。
- “初始化管理员”按钮。

客户端校验：

- 两次密码一致。
- 长度 8~256 字符。
- 不在本地日志、崩溃报告或埋点中记录。

成功行为：

- 服务端返回 `mustChangePassword=true`。
- APP 跳转登录页。
- 使用初始凭据登录后强制进入“修改密码”页。
- 修改成功后撤销旧会话并返回登录页。

失败行为：

- 初始化已完成：显示“管理员已初始化，请使用现有账号登录或联系管理员重置”，不得覆盖已有哈希。
- 密码策略失败：显示字段错误。
- 并发初始化：返回冲突，客户端不得自动重试创建。

## 4. 接口定义（函数签名级）

### 4.1 获取部署状态

```python
@dataclass(frozen=True)
class SetupStatus:
    initialized: bool
    admin_username: str
    must_change_password: bool
    server_time: str

GET /api/v1/setup/status() -> SetupStatus
```

响应禁止包含密码、密码哈希、Token、环境变量值或数据库路径。

### 4.2 初始化初始管理员

```python
class InitializeAdminRequest(BaseModel):
    password: str = Field(min_length=8, max_length=256)
    confirmPassword: str = Field(min_length=8, max_length=256)
    clientOperationId: UUID

@dataclass(frozen=True)
class InitializeAdminResponse:
    initialized: bool
    username: str
    mustChangePassword: bool
    serverTime: str
    traceId: str

POST /api/v1/setup/initialize-admin(
    body: InitializeAdminRequest,
    x_request_id: UUID,
    idempotency_key: UUID,
) -> InitializeAdminResponse
```

服务端规则：

- 仅当系统管理员不存在或处于明确的未初始化状态时允许一次成功初始化。
- `Idempotency-Key` 必须等于 `clientOperationId`。
- 同键同 payload 返回原结果；同键不同 payload 返回 `409 IDEMPOTENCY_PAYLOAD_MISMATCH`。
- 初始化事务必须锁定初始化状态，创建/更新管理员哈希并写审计。
- 初始化成功必须设置 `must_change_password=1`。
- 禁止通过空密码、默认密码、工号、URL 参数或无密码请求初始化。

### 4.3 首次改密

```python
class ChangePasswordRequest(BaseModel):
    oldPassword: str = Field(min_length=1, max_length=256)
    newPassword: str = Field(min_length=8, max_length=256)

POST /api/v1/auth/change-password(
    body: ChangePasswordRequest,
    authorization: BearerToken,
    x_request_id: UUID,
) -> ChangePasswordResponse
```

成功后：

- `must_change_password=0`
- 撤销该用户全部会话
- 返回“请重新登录”，不返回新密码或密码哈希

## 5. 数据结构定义

### 5.1 setup_state

```sql
setup_state(
  id TEXT PRIMARY KEY,
  state TEXT NOT NULL CHECK(state IN ('UNINITIALIZED','INITIALIZED')),
  admin_username TEXT NOT NULL,
  initialized_at TEXT,
  initialized_by TEXT,
  version INTEGER NOT NULL DEFAULT 1
)
```

### 5.2 users 关键字段

```text
users.id                  TEXT PRIMARY KEY
users.username            TEXT UNIQUE NOT NULL
users.password_hash       TEXT NOT NULL
users.role                TEXT NOT NULL
users.must_change_password INTEGER NOT NULL DEFAULT 1
users.active              INTEGER NOT NULL DEFAULT 1
```

禁止新增明文密码字段。

### 5.3 setup_operations

```sql
setup_operations(
  client_operation_id TEXT PRIMARY KEY,
  payload_digest TEXT NOT NULL,
  result_json TEXT NOT NULL,
  created_at TEXT NOT NULL
)
```

`result_json` 只能保存非敏感结果。

## 6. 技术选型及理由

- FastAPI + Pydantic：复用现有接口和校验体系，精确拒绝空密码和非法字段。
- Argon2id：复用现有密码哈希方案，避免新增算法路径。
- SQLite WAL + 事务锁：测试环境资源轻量，初始化是低频单次操作；生产迁移 PostgreSQL 时保留相同事务语义。
- Android Compose + ViewModel/StateFlow：与现有 APP 一致，页面状态可测试。
- `EncryptedSharedPreferences`：仅保存地址和会话摘要；不保存初始密码。
- `UUID clientOperationId`：防止网络重试导致重复初始化。

## 7. 权限与状态机

```text
UNINITIALIZED
  └─ initialize-admin（一次成功）→ INITIALIZED + mustChangePassword=1
       └─ login → PASSWORD_CHANGE_REQUIRED
            └─ change-password → AUTHENTICATED
```

`PASSWORD_CHANGE_REQUIRED` 状态下：

- 允许：`/healthz`、登录、改密、必要的登出/会话撤销。
- 拒绝：订单、库存、扫码业务、用户管理、审批、审计读取等业务接口，统一返回 `403 PASSWORD_CHANGE_REQUIRED`。

## 8. 验收标准

- [ ] 首次安装/重置后，APP 能从登录页进入部署向导。
- [ ] 不输入密码不能完成管理员初始化。
- [ ] 服务端永不返回密码或密码哈希。
- [ ] 初始化后登录响应包含 `mustChangePassword=true`。
- [ ] 改密前访问业务接口返回 `403 PASSWORD_CHANGE_REQUIRED`。
- [ ] 改密成功后旧密码失效且会话撤销。
- [ ] 初始化接口幂等且并发只有一个成功者。
- [ ] ADMIN 用户管理页只能由已完成首次改密的 ADMIN 使用。
- [ ] 测试数据重置不覆盖管理员哈希和 setup 状态。
- [ ] Android 单测、后端 pytest、契约测试和部署回读全部通过。
