# 后端地址配置说明

客户端**不硬编码**任何真实服务器地址。API 根地址在构建期注入，
仓库内的源码、文档、构建脚本只保留占位值 `https://api.example.invalid`。

## 注入方式

三种方式任选其一，优先级从高到低：

| 方式 | 命令 / 位置 |
| --- | --- |
| 命令行参数 | `./gradlew assembleDebug -PapiBaseUrl=https://api.your-domain.com` |
| `gradle.properties` | 在 `logistics-android/gradle.properties` 加一行 `apiBaseUrl=https://api.your-domain.com` |
| 环境变量 | `export API_BASE_URL=https://api.your-domain.com` |

> `gradle.properties` 中若写入真实地址，请勿提交到公开仓库；
> 本地可用 `gradle.properties`，CI 建议用环境变量或命令行参数。

## 注入后的取值链路

```
build.gradle.kts  apiBaseUrl 变量
        ↓  buildConfigField("String", "API_BASE_URL", ...)
BuildConfig.API_BASE_URL
        ↓
ApiConfig.baseUrl
        ↓
MaterialFlowApi 请求
```

## 构建示例

```bash
cd logistics-android

# 指向测试服务器
./gradlew assembleDebug -PapiBaseUrl=http://10.0.0.5:8000

# 指向正式环境（须 HTTPS）
./gradlew assembleRelease -PapiBaseUrl=https://api.your-domain.com
```

## 未注入时会怎样

回落到 `https://api.example.invalid`，该域名不可解析，
所有网络请求会立即失败。这是刻意设计——**宁可连不上，也不要误连到某个真实环境**。

## 正式发布前必须处理的两项

1. **启用 HTTPS**：`AndroidManifest.xml` 当前有 `usesCleartextTraffic="true"`
   （为便于内网测试）。正式包必须移除，并配合 HTTPS 域名。
2. **替换 debug 签名**：Release 包需用正式 keystore 签名，
   `app-debug.apk` 仅限内部测试安装，不可对外分发。
