# 实测结论（2026-11-25，真实 U9 `http://192.168.2.251/u9c`，库 `U920261010`）

上面是 U9 方给的接口规格。实际联调发现**规格与真实网关行为有多处不一致**，以下每条都经过真实请求验证，改代码前必读。

## 1. `ReturnFields` 必须是字符串数组

```
"ReturnFields": ["DocNo", "Status.Value", ...]        → OK
"ReturnFields": "DocNo,Status.Value,..."              → ResCode=502 参数错误
```

逗号拼接的字符串会被判参数错误。字段名写错反而是静默忽略（不报错、该字段为空），所以**参数类型错误才会暴露**，单测用假 transport 测不出来。

## 2. 排序只能用 `Orders`，方向必须小写

```
"Orders": "DocNo asc"                 → OK，分页稳定
"Orders": "DocNo ASC"                 → 被拒
"OrderBy": "DocNo"（任何写法）         → ResCode=500 Syntax Error ... 当编译 OQL: order by
```

U9 网关只认 `Orders`；`OrderBy` 是另一套（OQL）语义，必然报错。

## 3. 比较操作符 gt / ge / lt 语义是**反的**

| 传入（`Orders: "BusinessDate desc"`） | 实际返回 |
|---|---|
| `gt "2026-10-01"` | 2026-09-30 及更早（相当于 `<`）|
| `ge "2026-10-01"` | 2023 年起的全部早期单据（相当于 `≤`）|
| `lt "2026-10-01"` | 2026-10-09 的单（相当于 `>`）|
| `lt "2026-10-09"` | 空（相当于 `>` 10-09，而库里最新就是 10-09）|
| `eq "2026-10-09"` | 正常，返回 10-09 当天 |

**红线：不要用 gt/ge/lt 做日期过滤。** 依赖这个反向语义，一旦 U9 升级修正，我们不会报错，只会静默漏掉最新单据——对缺料「在途量」是致命错误。日期窗口一律拉回来在本地过滤。

## 4. `Status` 不能做过滤条件

```
Filter: {"Field": "Status.Name", "Operator": "eq", "Value": "Approved"}
→ ResCode=500 Type UFIDA.U9.PM.PO.PODOCStatusEnum introduced in Status at state Entity is not one kind of entity
```

`Status.Value` 同样报错。状态只能在本地按返回的 `Status.Name` 筛。

## 5. 不认识的参数/操作符会被静默忽略

`greaterThan`、`like "2026-10%"` 都不报错，直接返回未过滤的结果（`like` 甚至返回空）。所以**任何过滤条件都必须用「结果是否真的变少」来验证**，不能只看 HTTP 200。

## 6. 可用且行为正常的过滤：`POLines.ItemInfo.ItemCode in`

```
{"Field": "POLines.ItemInfo.ItemCode", "Operator": "in",
 "Value": "30313003-00131,30313003-00132", "Logic": "and"}
```

返回的确实是包含这些料号的单据，行为符合预期。需要按料号收敛数据量时可以用。
