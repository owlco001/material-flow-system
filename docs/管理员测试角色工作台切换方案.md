# 管理员测试角色工作台切换方案

## 1. 目标与边界

测试阶段允许 `ADMIN` 用户在 Android 工作台内切换查看四种角色的工作台视图：

- `OPERATOR`：操作员
- `MATERIAL`：物料员
- `WAREHOUSE_ADMIN`：仓库管理员
- `ADMIN`：管理员

该能力用于测试工作台布局、状态卡片、列表筛选、空态、错误态和角色导航，不改变登录用户的真实角色，不授予管理员以外的业务权限，不改变数据库中的用户角色。

正式启用时默认关闭。公司内网正式环境如需保留，必须通过服务端显式配置开启，并继续保留 ADMIN-only、审计和不可提权约束。

## 2. 安全决策

1. 服务端认证角色仍是唯一真实权限来源。
2. `viewRole` 只是工作台展示上下文，不是授权角色。
3. 预览模式下禁止执行领取、到工位、出库审批、出库执行、交接确认、驳回、取消等业务写操作。
4. 所有预览请求必须由已认证 `ADMIN` 发起；普通角色传入 `viewRole` 返回 `403`。
5. 服务端配置 `ENABLE_ADMIN_ROLE_PREVIEW` 默认值为 `false`；未开启时即使 ADMIN 也返回 `404 ROLE_PREVIEW_DISABLED`，避免生产误用。
6. 每次切换和每次预览查询写入脱敏审计事件，记录真实操作者、目标视图角色、requestId、serverTime 和 clientOperationId，不记录 Token 或密码。
7. 客户端隐藏切换入口只属于 UX，后端必须重复校验 ADMIN 和配置开关。

依赖方向固定为：UI → ViewModel → Repository → API；`previewRole` 不写入用户角色、不覆盖 Token claims、不改变服务端权限中间件。

## 4. 接口定义

### 4.1 Android 函数签名

```kotlin
enum class WorkspaceViewRole {
    OPERATOR, MATERIAL, WAREHOUSE_ADMIN, ADMIN
}

data class WorkspaceQueryContext(
    val authenticatedRole: UserRole,
    val viewRole: WorkspaceViewRole,
    val preview: Boolean
)

interface AdminRolePreviewController {
    fun enterPreview(role: WorkspaceViewRole): Result<WorkspaceQueryContext>
    fun exitPreview(): Result<WorkspaceQueryContext>
    fun currentContext(): WorkspaceQueryContext
}

interface RoleWorkspaceRepository {
    suspend fun loadRoleSummary(
        viewRole: WorkspaceViewRole? = null,
        requestId: String
    ): Result<RoleSummary>

    suspend fun listWorkItems(
        viewRole: WorkspaceViewRole? = null,
        status: String?,
        orderNo: String?,
        page: Int,
        pageSize: Int,
        requestId: String
    ): Result<PagedMaterialWorkItems>
}
```

约束：

- `viewRole != null` 仅允许当前认证用户为 `ADMIN`。
- `preview=true` 时所有动作按钮必须为禁用态，并显示明确提示。
- 退出预览恢复 `ADMIN` 视图，不触发登出、不刷新 Token。
- `previewRole` 只保存在内存；进程退出后恢复真实 ADMIN 工作台，不能持久化为角色。

### 4.2 REST API

#### 工作台摘要

```http
GET /api/v1/workspace/summary?viewRole=OPERATOR
Authorization: Bearer <access-token>
X-Request-Id: <uuid>
X-Client-Operation-Id: <uuid>
```

响应 `200`：沿用现有 `RoleSummary`，并增加：

```json
{
  "role": "OPERATOR",
  "preview": true,
  "authenticatedRole": "ADMIN",
  "pendingApprovalCount": 0,
  "pendingOutboundCount": 0,
  "pendingHandoverCount": 0,
  "atStationCount": 0,
  "pickedUpCount": 0,
  "outOfStockCount": 0,
  "generatedAt": "2026-01-01T00:00:00Z"
}
```

#### 工作项分页

```http
GET /api/v1/workspace/material-items?viewRole=MATERIAL&status=OUTBOUND_PENDING&orderNo=26B-013&page=1&pageSize=20
Authorization: Bearer <access-token>
X-Request-Id: <uuid>
X-Client-Operation-Id: <uuid>
```

响应 `200`：沿用现有分页结构，并返回 `preview=true`、`authenticatedRole=ADMIN` 元数据。

#### 服务端错误

- 未登录：`401 UNAUTHORIZED`
- 非 ADMIN 传 `viewRole`：`403 ROLE_PREVIEW_ADMIN_ONLY`
- 配置关闭：`404 ROLE_PREVIEW_DISABLED`
- 非法角色值：`400 INVALID_VIEW_ROLE`
- 预览状态调用写接口：`403 ROLE_PREVIEW_READ_ONLY`

### 4.3 审计事件

```python
def append_role_preview_audit(
    *,
    actor_user_id: str,
    actor_role: str,
    view_role: str,
    action: str,  # ENTER, QUERY, EXIT
    request_id: str,
    client_operation_id: str,
    server_time: datetime,
) -> None:
    ...
```

`action` 只允许 `ENTER`、`QUERY`、`EXIT`。审计事件必须脱敏，不保存 Authorization header、密码、完整请求体或网络地址。

## 5. 数据结构定义

### 5.1 请求上下文

```python
@dataclass(frozen=True)
class WorkspaceViewContext:
    authenticated_user_id: str
    authenticated_role: Literal["ADMIN"]
    view_role: Literal["OPERATOR", "MATERIAL", "WAREHOUSE_ADMIN", "ADMIN"]
    preview: bool
    request_id: str
    client_operation_id: str
```

### 5.2 审计事件字段

新增事件类型：`ADMIN_ROLE_PREVIEW`。

- `id TEXT PRIMARY KEY`
- `event_type TEXT NOT NULL`
- `entity_type TEXT NOT NULL DEFAULT 'WORKSPACE'`
- `entity_id TEXT NOT NULL DEFAULT 'ROLE_PREVIEW'`
- `actor_user_id TEXT NOT NULL`
- `actor_role TEXT NOT NULL CHECK(actor_role = 'ADMIN')`
- `view_role TEXT NOT NULL`
- `action TEXT NOT NULL CHECK(action IN ('ENTER','QUERY','EXIT'))`
- `request_id TEXT NOT NULL`
- `client_operation_id TEXT NOT NULL`
- `server_time TEXT NOT NULL`

不新增用户角色，不修改 `users.role`，不复制用户权限记录。

## 6. 技术选型及理由

- Android 采用内存态 `WorkspaceQueryContext`：测试切换即时、无数据库迁移、进程重启自动回到真实 ADMIN，降低误把测试角色带入正式操作的风险。
- FastAPI 采用查询参数 `viewRole`：向后兼容现有工作台接口，不新增平行接口，客户端和旧版本可以继续请求无参数的真实角色视图。
- 服务端使用配置开关：默认关闭，测试环境按环境变量开启，正式环境可通过部署配置关闭。
- 只读投影而非身份模拟：避免测试功能绕过真实权限，也避免管理员误执行其他角色的业务动作。
- 审计沿用现有 `audit_events`：切换和查询可追溯，避免引入第二套日志系统。
- 中端 Android 设备限制：只保留当前预览角色、分页 20 条工作项，不缓存四种角色的全量数据；切换时取消上一次请求，最大并发 2。

## 7. 验收标准

1. ADMIN 能在内存中切换 `OPERATOR`、`MATERIAL`、`WAREHOUSE_ADMIN`、`ADMIN` 四种视图。
2. 切换不改变登录用户角色、Token、用户资料和服务端权限。
3. 每种视图的摘要和工作项按对应角色的只读过滤规则返回。
4. 非 ADMIN 传 `viewRole` 返回 `403 ROLE_PREVIEW_ADMIN_ONLY`。
5. 配置关闭时 ADMIN 传 `viewRole` 返回 `404 ROLE_PREVIEW_DISABLED`。
6. 预览页面明确显示“测试预览，只读，不代表当前账号权限”。
7. 预览状态下所有业务写操作不可执行；服务端直接调用写接口返回 `403 ROLE_PREVIEW_READ_ONLY`。
8. 进入、查询、退出均产生 `ADMIN_ROLE_PREVIEW` 审计事件，且不含密码、Token、source_ip 等敏感字段。
9. 进程重启、退出登录和 refresh 失效后，预览状态清除并回到真实身份流程。
10. 测试环境使用固定脱敏数据；正式内网环境关闭开关时，旧工作台接口行为不受影响。
