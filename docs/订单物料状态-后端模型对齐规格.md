# 26B-013 订单物料状态后端模型对齐规格

## 1. 目的

将订单 `26B-013` 的设备 BOM 与物料状态接入后端正式查询链路，避免测试数据只存在于临时扩展表而 API 无法读取。

VPS 测试数据库中的真实路径、主机信息、设备编号、备份文件名和任何认证信息不得写入 Git。本文只记录脱敏后的模型和接口规则。

## 2. 当前问题（已核对）

后端当前 `/api/v1/orders/material-status` 实现只查询 `materials` 主数据，并将每条主数据返回为订单物料状态；它没有按 `documentNo` 查询订单，也没有读取订单 BOM。

数据库当前存在：

- `production_orders`：1 条测试订单
- `order_devices`：25 台设备
- `order_materials`：75 条订单物料匹配记录
- `materials`：现有物料主数据
- 不存在 `order_material_requirements`

因此不能通过简单重命名解决：`order_materials` 是“设备 BOM 匹配”模型，正式 API 还需要“订单需求关联物料主数据”的 `material_id` 外键。

## 3. 正式数据模型

### 3.1 production_orders

```sql
production_orders(
  id TEXT PRIMARY KEY,
  order_no TEXT UNIQUE NOT NULL,
  product_name TEXT NOT NULL,
  status TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
)
```

### 3.2 order_devices

```sql
order_devices(
  id TEXT PRIMARY KEY,
  order_id TEXT NOT NULL REFERENCES production_orders(id) ON DELETE CASCADE,
  device_type TEXT NOT NULL,
  device_no TEXT UNIQUE NOT NULL,
  sequence_no INTEGER NOT NULL,
  created_at TEXT NOT NULL,
  UNIQUE(order_id, device_type, sequence_no)
)
```

### 3.3 order_material_requirements（正式 API 读取表）

```sql
order_material_requirements(
  id TEXT PRIMARY KEY,
  order_id TEXT NOT NULL REFERENCES production_orders(id) ON DELETE CASCADE,
  device_id TEXT REFERENCES order_devices(id) ON DELETE CASCADE,
  material_id TEXT NOT NULL REFERENCES materials(id),
  required_quantity INTEGER NOT NULL CHECK(required_quantity > 0),
  arrived_quantity INTEGER NOT NULL DEFAULT 0 CHECK(arrived_quantity >= 0),
  in_stock_quantity INTEGER NOT NULL DEFAULT 0 CHECK(in_stock_quantity >= 0),
  status_code TEXT NOT NULL CHECK(status_code IN ('OUT_OF_STOCK','ARRIVED','IN_STOCK')),
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  CHECK(arrived_quantity <= required_quantity),
  CHECK(in_stock_quantity <= arrived_quantity),
  UNIQUE(order_id, device_id, material_id)
)
```

`material_id` 必须指向 `materials.id`，不能把 `material_code` 当作外键，也不能把设备编号当成物料。

## 4. 26B-013 测试数据映射规则

订单固定为：

- 订单号：`26B-013`
- 产品：`自动化流水线设备`
- 设备总数：25 台
- 横向输送机：10 台
- 十字输送机：10 台
- 缓存：3 台
- 合片机：2 台

每台设备的 3 条 BOM 需求必须映射到 `materials` 中的真实主数据。当前仅有 1 条物料主数据，不能伪造 75 个 `material_id`。

开发实现必须先补齐脱敏的测试物料主数据（例如控制柜、位置传感器、输送驱动组件对应的稳定测试物料编码），再创建 75 条 `order_material_requirements`。每台设备三类物料的状态可随机，但最终必须至少覆盖：

- `OUT_OF_STOCK`
- `ARRIVED`
- `IN_STOCK`

随机只允许使用固定 seed 的测试种子，确保重复执行可复现；生产数据禁止使用随机编号和随机状态。

## 5. API 函数签名

```python
def material_status(
    body: OrderMaterialStatusRequest,
    user: sqlite3.Row = Depends(current_user),
) -> OrderMaterialStatusResponse:
    ...
```

请求模型：

```python
class OrderMaterialStatusRequest(BaseModel):
    documentNo: str = Field(min_length=1, max_length=64)
    documentType: Literal['ORDER_NO'] = 'ORDER_NO'
```

查询逻辑：

1. `documentType == 'ORDER_NO'` 时按 `production_orders.order_no` 精确查询。
2. 订单不存在返回 HTTP `404`，错误码 `ORDER_NOT_FOUND`。
3. 通过 `production_orders.id` 查询 `order_material_requirements`。
4. JOIN `materials` 获取物料编码、名称、规格、单位。
5. JOIN `order_devices` 获取设备类型和设备编号。
6. 按设备序号、物料编码升序返回。
7. 结果中的 `requiredQuantity`、`arrivedQuantity`、`inStockQuantity`、`statusCode` 必须来自需求表，不得用库存主表数量替代。

响应项目字段：

```python
class OrderMaterialStatusItem(BaseModel):
    requirementId: str
    deviceId: str | None
    deviceType: str | None
    deviceNo: str | None
    materialId: str
    materialCode: str
    materialName: str
    specification: str | None
    unit: str
    requiredQuantity: int
    arrivedQuantity: int
    inStockQuantity: int
    statusCode: Literal['OUT_OF_STOCK', 'ARRIVED', 'IN_STOCK']
```

响应模型：

```python
class OrderMaterialStatusResponse(BaseModel):
    documentNo: str
    documentType: Literal['ORDER_NO']
    orderId: str
    productName: str
    orderStatus: str
    items: list[OrderMaterialStatusItem]
    serverTime: str
```

## 6. 验收标准

- 请求 `documentNo=26B-013` 返回 HTTP `200`。
- 返回订单号为 `26B-013`，产品为自动化流水线设备。
- 返回 25 台设备关联的物料需求，不返回无关订单数据。
- 每台设备至少 3 条物料需求，总需求条数为 75 条（以种子数据为准）。
- 所有 `materialId` 都能在 `materials` 表找到。
- 三种状态均存在，状态与数量满足：缺货到货数为 0；已到货在库数为 0；在库数量等于需求数量。
- 不传认证、订单不存在、文档类型非法时分别返回既定错误，不泄露数据库路径或服务器信息。
- 重复执行测试种子不产生重复订单、设备或需求。
- 单元测试覆盖订单不存在、物料外键不存在、状态数量约束和重复种子。
