# V1 交接与审批契约

## 1. 领域关系

```text
production_orders
  -> order_material_requirements
  -> material_work_items
  -> transfer_requests (OUTBOUND)
  -> material_handovers
  -> audit_events
```

`order_material_requirements` 是订单需求事实来源；`material_work_items` 是面向角色工作台的投影，使用 `work_item_id` 唯一关联，不得形成第二套数量事实。工作台投影由服务端事务内更新或由可重放任务重建。

## 2. 状态与权限

- 操作员：查看本人负责范围；确认领取和到机台交接。
- 物料员：查看待出库/已出库；发起出库交接，不得审批。
- 仓库管理员：审批入库/出库；确认或驳回仓库侧交接。
- 管理员：全量查看、审批、确认、审计查询。

出库必须先创建 `transfer_requests(type=OUTBOUND)`，经仓库管理员或管理员审批后，才可执行出库。交接接口必须携带 `transferRequestId`，不得绕过审批直接扣减库存。

## 3. 接口

```text
POST /api/v1/handovers
  body: {workItemId, transferRequestId, quantity, fromLocation,
         deviceId, receiverUserId|null, remark|null, clientOperationId}

POST /api/v1/handovers/{handoverId}/confirm
  body: {clientOperationId, requestId}

POST /api/v1/handovers/{handoverId}/reject
  body: {clientOperationId, requestId, reason}

POST /api/v1/handovers/{handoverId}/cancel
  body: {clientOperationId, requestId, reason}
```

所有写请求必须同时满足：`Authorization: Bearer <accessToken>`、`X-Request-Id: <uuid>`、`Idempotency-Key: <clientOperationId>`，且 body 中 `clientOperationId` 与 Header 完全相同。相同幂等键和相同 payload 返回原结果；相同幂等键但 payload 不同返回 `409 IDEMPOTENCY_PAYLOAD_MISMATCH`。

## 4. 事务规则

- 创建交接：只创建 `PENDING` 记录和审计，不扣库存。
- 出库执行：审批通过后，在 `BEGIN IMMEDIATE` 事务中校验库存版本、数量、库位和工作项版本，更新库存/流转单/工作项并产生 `OUTBOUND_CONFIRMED`。
- 确认交接：校验目标 `deviceId`、接收人身份和当前状态；更新交接、工作项和审计，产生 `PICKED_UP`，目标为订单机台时产生 `AT_STATION`。
- 驳回/取消：只允许 `PENDING`，必须记录原因和操作者；已确认记录不得回退。
- 任一步失败全部回滚；冲突返回 `409`，不得部分成功。

## 5. 验收门禁

- 审批前出库和交接确认不能扣库存。
- 非审批角色返回 `403`。
- 重复确认/驳回/取消返回稳定 `409`，不产生第二条审计事件。
- 时间线能看到创建、审批、出库、领取、到机台的完整服务端时间序列。
