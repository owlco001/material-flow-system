# 功能与性能优化章程

## Mission
在保持厂内物料业务与接口兼容的前提下，修复可复现的正确性缺陷，降低装配列表查询和客户端同步的开销。

## 首轮范围（历史）
首轮聚焦五个可独立验证的切片：流转执行的库存一致性；清除被主路由遮蔽的装配列表重复入口并锁定查询预算；仓库库存优先排序索引；Android 离线同步完整性；Android 盘点刷新与分页并发一致性。最终统一回归与报告。不扩展成全库重构。

## 2026-11-20 第二轮修复范围
基线138ff95；分支fix-deep-audit-138ff95。按深查报告处理：会话身份epoch与登录/刷新提交、取消claim恢复、装配分页及工时生命周期、工时报表集合关联、工作台状态筛选轻量分页、重复车间路由；Web订单物料先量化并迁移筛选后复用既有API分页。原非目标与权限不变，旧队列账号归属不做隐式迁移。

## Critical Workflows
- 申请、审批、执行流转的角色、乐观锁、幂等与整单回滚。
- 装配任务列表的权限范围、分页、排序及人员信息。
- 离线操作入队、退避、重试终态、幂等键及会话变化后停止旧批次；持久化账号归属仍按D6单独处理。
- 盘点第一页刷新、加载更多及失败恢复。

## External Surfaces
既有 REST/管理台响应字段、SQLite 数据、Android Room 队列结构、版本配置和测试流程。性能测量仅用合成数据与临时库。

## Invariants
保持现有业务契约和权限；不修改已有生产数据或部署；不读取或输出凭据；原始本地仓库保持不变；每项修复有失败前/成功后行为证据；已有基线失败必须单独报告。

## Non-Goals
不部署、不推送、不引入新业务或库存小数改造，不修改内网 HTTP 定案，不重新设计界面或替换技术栈。

## Guardrails
独立工作副本 /tmp/material-flow-optimization；首轮分支optimize-function-performance，当前第二轮分支fix-deep-audit-138ff95。实现前登记切片；并行写入范围互不重叠；所有变更文件登记 MAP.csv；替代逻辑在本切片删除；临时实验不得留在产品代码；最终保留一项 convergence 切片复核。

## Ship Gate
运行完整后端 pytest、4项独立脚本测试、Android testDebugUnitTest 和 assembleDebug、emoji 门禁、git diff --check、自定义优化回归 guard。对变化路径做差异复核和残留扫描。记录基线/修改后查询数与同机合成数据用时，性能测试不使用易波动的绝对耗时断言。真机离线/扫码与生产 U9 验收超出本环境验证范围，须明确列出。
