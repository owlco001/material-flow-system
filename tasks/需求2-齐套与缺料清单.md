# 需求 2 · 工单齐套情况 + 缺料清单

> 基线：main @ 76d1965（后端 0.23.0）　来源：老王 2026-10-27 需求第 2 条
> 目标：按项目/机台查齐套情况，并输出可执行的缺料清单（缺什么、缺多少、影响谁）

## 现状（已核实）

- `POST /api/v1/orders/material-status`（`main.py:4286`）已返回：`items[]`（required / arrived / inStock / statusCode / shortageQuantity）、`materialSummary`、`shortageLineCount`、分页与 `hasMore`
- 缺料量计算已有：`shortageQuantity = max(required - in_stock, 0)`（`main.py:3443`、`3490`），`totalShortageQuantity`（`3454`、`3500`）
- 齐套率按全量算，不随分页变化（`main.py:4376` 注释）
- 管理台已有 `/admin/orders`、`/admin/reports`

## 缺口

1. 缺「缺料清单」聚合视图：现在的接口是**单订单分页明细**，没有一个「只列缺料、按缺口排序、跨机台汇总」的清单
2. 缺「哪些机台被这条缺料卡住」的关联（同一料号影响多台机台时应合并成一行并列出机台号）
3. 缺导出（车间/采购要拿纸质或 Excel 去催料）
4. 「工单」维度口径未定：需求行是按 `order_devices`（机台）记的，`assembly_tasks` 才是现场工单

## 功能要求

1. **齐套概览**（按项目或按订单）
   - 输入项目号/订单号 → 返回：机台数、需求行数、齐套行数（`ARRIVED` + `IN_STOCK`）、缺料行数、齐套率（按需求行，保留 1 位小数）、缺料料号数（去重）
   - 按机台分组：每台机台的齐套率、缺料行数、卡点料号 Top3
2. **缺料清单**（核心）
   - 列：料号、品名、规格、单位、总缺口量、影响机台数、影响机台号（逗号分隔，超过 5 个折叠为「等 N 台」）、最不利状态（无在库/部分到货）、关联订单号
   - 默认按「缺口量降序 + 影响机台数降序」；支持按机台号/料号过滤
   - 同料号跨机台必须合并（不能一个机台一行刷屏）
3. **导出 xlsx**：齐套概览 + 缺料清单两个 sheet（复用 `app/xlsx_writer.py`，注意控制字符过滤已在 0.23.0 修好）
4. **权限**：ADMIN / WORKSHOP_SUPERVISOR / PLANNER 可查；ASSEMBLER 只看本人参与机台（与需求 1 同口径，越权 403 而非空数据）；WAREHOUSE_ADMIN 可查（仓库需要催料清单）
5. **不造假**：无需求记录的料号不进缺料清单；缺口为 0 的行不出现；分页默认 50，最大 200

## 接口

- `GET /api/v1/projects/{project_no}/kitting-summary` → 概览 + 按机台分组
- `GET /api/v1/projects/{project_no}/shortage-list?device_no=&material_code=&page=&pageSize=` → 合并后的缺料清单（分页）
- `GET /api/v1/projects/{project_no}/shortage-list/export` → xlsx（两 sheet）
- 复用 `_pmr_*` 的项目解析与权限函数（`main.py:4756-4823`），不要重复实现
