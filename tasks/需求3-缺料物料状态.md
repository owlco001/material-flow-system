## 四档状态定义

对每一条缺料（`order_material_requirements` 中 `procureGap > 0` 的料号）：

1. `IN_STOCK_READY` **在库可满足**：库存可用量 ≥ 需求缺口
2. `ARRIVED_NOT_STOCKED` **已到货待入库**：未入库，但未结案采购订单的已到货量（`TotalRecievedQtyTU`）≥ 缺口
3. `IN_TRANSIT` **在途采购**：未结案采购订单未到货量（`PurQtyTU − TotalRecievedQtyTU`）≥ 缺口（或部分覆盖，给「可覆盖量」字段）
4. `NO_PLAN` **无采购计划**：以上都不足以覆盖缺口，且无未结案采购订单 → 真缺，需要下采购

判定顺序严格按 1→2→3→4（先易后难），并输出每个料号的明细：在库量、已到货未入库量、在途量、未结案 PO 号与供应商。

## 实施内容

### 1. U9 采购订单同步（后端）

- `app/u9/client.py` 新增 `fetch_purchase_orders(since_days=180, only_open=True)`：
  - 优先走 `POST /webapi/CommonEntity/Query`（`EntityFullName=UFIDA.U9.PM.PO.PurchaseOrder`），`ReturnFields` 必须包含 `DocNo / BusinessDate / Status.Value / Status.Name / Supplier_Code / DeliveryDate / POLines.DocLineNo / POLines.ItemInfo.ItemCode / POLines.ItemInfo.ItemName / POLines.PurQtyTU / POLines.TotalRecievedQtyTU`
  - 取回后**校验字段存在性**（缺 `TotalRecievedQtyTU` 时直接报错，不得静默当 0）
- `app/u9/sync.py` 增加 entity `po`（幂等：按 `DocNo + DocLineNo` upsert）
- 新表（`CREATE TABLE IF NOT EXISTS`，不改既有表）：
  - `u9_po_headers(id, doc_no UNIQUE, status_value, status_name, supplier_code, supplier_name, business_date, org_code, synced_at)`
  - `u9_po_lines(id, doc_no, line_no, item_code, item_name, pur_qty_tu, recieved_qty_tu, delivery_date, synced_at, UNIQUE(doc_no, line_no))`
- 同步入口复用既有 `/api/v1/u9/sync/{entity}`，`entity=po`；管理台 `/admin/u9` 出现该实体（跟现有条目同样的按钮与 dry-run）

### 2. 需求 2 的缺料清单接入状态

- `shortage-list` 每行新增：`stockStatus`（四档 code + 中文 label）、`availableStockQty`、`arrivedNotStockedQty`、`inTransitQty`、`openPoNos[]`、`suppliers[]`
- `procureGapQuantity` / `prepareGapQuantity` 口径不变，四档是**在其之上叠加的判断**，不得改动已核对过的数字
- 概览增加 `statusBreakdown: {IN_STOCK_READY: n, ARRIVED_NOT_STOCKED: n, IN_TRANSIT: n, NO_PLAN: n}`（按缺料料号数）
- 支持 `status=` 过滤

### 3. 管理台

- `/admin/projects/kitting` 缺料清单加「物料状态」列（四色标签）+ 过滤下拉；导出 xlsx 同步加列
- 页头提示「采购数据同步于 YYYY-MM-DD HH:mm，共 N 张未结案订单」（体现数据新鲜度；超过 24 小时未同步时标黄）

### 4. 数据新鲜度与降级

- 若 `u9_po_*` 为空（从未同步）：状态一律 `NO_PLAN` 并在响应里 `poDataFresh=false`，页面顶部显示「采购数据未同步，状态判断不可信」——不得假装有数据
- 若某料号在 U9 里查不到（料号体系不一致）：标 `UNKNOWN_MATERIAL` 而不是塞进 NO_PLAN
