# 需求 1 · 项目物料需求（按设备展开到底）

> 基线：main @ 待定（后端 0.22.0）　来源：老王 2026-10-27 需求第 1 条
> 目标：输入项目号 → 看到该项目下每台设备的备料需求量，可逐层展开到叶子件

## 数据源（已核实存在）

- 项目 = `production_orders`（U9 项目号 = 订单号，见 `u9` 同步口径）
- 设备/机台 = `order_devices`（`main.py:818`），`device_no` 唯一
- 备料表（工程BOM 聚合）= `agg_bom_items`（`main.py:808`）：`batch_id / device_code / device_name / level_no / parent_code / material_code / material_name / specification / unit / quantity / material_form / line_no`
  - `level_no` + `parent_code` 足以还原 BOM 层级树，`quantity` 是该层级用量
- 物料需求（含到货/在库状态）= `order_material_requirements`（`main.py:817`）：`required_quantity / arrived_quantity / in_stock_quantity / status_code`

## 功能要求

1. 查询入口：输入项目号（或从订单列表点进），支持模糊匹配项目号/项目名
2. 结果分组：项目 → 机台（device_no / device_name）→ BOM 层级（父件下挂子件）
3. 每行显示：料号、品名、规格、单位、单机用量、该机台合计需求、层级
4. 展开/收起：默认只展开第一层，可一键全部展开到叶子；显示「共 N 项、M 层」
5. 与物料需求状态联动：若该料在 `order_material_requirements` 中有记录，附带显示 到货量/在库量/状态（缺料/到货/在库）；没有记录则留空，不得显示 0 冒充
6. 空与异常：项目不存在 / 无备料表批次 / 无设备 三种情况给明确中文提示，不显示空白页
7. 导出：当前项目物料需求明细导出 xlsx（保留层级与合计行）

## 接口

- `GET /api/v1/projects/{project_no}/material-requirements?expand=all|top&device_no=` → 结构化树
- `GET /api/v1/projects/{project_no}/material-requirements/export` → xlsx
- 权限：沿用现有订单查询权限（ADMIN / WORKSHOP_SUPERVISOR 可见；ASSEMBLER 仅本人参与机台）
- 不新增表、不改既有表结构

## 管理台

- 新增路由 `/admin/projects/material-requirements`（或挂在 `/admin/orders` 下的子页），输入项目号查询
- 表格 + 树形展开，样式沿用现有 admin 模板

## 验收

- 后端 pytest 全绿且新增用例覆盖：层级还原、多机台分组、无备料批次、权限（ASSEMBLER 只见自己机台）、导出列
- 管理台页面可实际查询并展开（人工或 e2e 截图证据）
- 不改变既有 `/api/v1/orders/*` 行为

## 备注

- 若某项目存在多个 `agg_bom` 批次，取最新 `batch_id`（按 created_at 倒序），并在页面标注批次时间
