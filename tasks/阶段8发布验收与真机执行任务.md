# 阶段 8 发布验收与真机执行任务

## 目标

在不把未执行的真机结果写入仓库的前提下，完成 Android 实体设备与后端发布版本的一致性验收。

## 前置条件

- 使用项目规定的 Android SDK 环境变量构建，不把真实地址、账号、密码、令牌或设备序列号写入仓库。
- 后端发布包必须使用 `material-flow-backend/VERSION` 作为唯一版本来源。
- 迁移命令必须在服务启动前执行，服务只监听本机回环地址，由受控反向代理或内网入口转发。
- Android Debug 仅用于受控内网验收；正式版只允许 HTTPS。

## Android 真机验收顺序

1. 安装已验证的 APK，并记录包名、版本和 SHA-256 到仓库外的验收记录。
2. 首次启动检查品牌开屏、动画减少设置和正常进入登录页。
3. 拒绝相机权限，确认出现原因说明、手动输入入口和再次授权/系统设置入口。
4. 授权相机，确认预览出现；离开页面、进入后台、返回页面后确认相机释放并可重新绑定。
5. 使用测试账号验证保持登录、冷启动恢复和 refresh 失效回登录。
6. 分别使用四类角色验证工作台：操作员、物料员、仓库管理员、管理员；状态必须来自服务端字段。
7. 验证交接确认、驳回、取消、审批、执行、审计时间线和重复点击；冲突应显示可行动的 `409` 提示并刷新。
8. 注入工作台 401、403、404、409、5xx、超时和合法空页，确认分别显示登录、权限、接口不可用、状态冲突、重试和空数据状态。
9. 结束后退出登录、清理应用数据和临时日志，恢复设备动画、网络和权限策略。

## 后端发布验收顺序

1. 在发布环境外先执行显式迁移入口两次，确认无重复表、重复种子或数据数量变化。
2. 启动服务前核对迁移命令、监听地址、端口和环境文件来源；不得把环境文件内容复制到仓库或聊天。
3. 读取 `/healthz`，确认 `version` 与 `VERSION` 文件一致，`service` 为项目服务名。
4. 验证认证、工作台、交接、出库、审计接口及角色权限。
5. 对审计响应做脱敏检查，确认不包含 `source_ip`、数据库路径、主机信息、令牌或原始堆栈。
6. 记录部署前后版本、迁移结果和健康检查结果到仓库外的发布记录。

## 证据与边界

- 代码构建通过不等同于实体真机通过；真机结果必须由实际设备执行后填写。
- 任何失败都记录复现步骤、脱敏错误摘要和回滚动作，不提交原始日志、抓包、凭据或真实设备标识。
- 当前任务文档不声明真机已经完成，也不声明真实 VPS 已经部署。
