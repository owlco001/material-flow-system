# 订单 26B-013 后端数据模型对齐任务

## 目标

将测试订单 `26B-013` 从临时 `order_materials` 模型迁移到后端 API 正式读取的订单物料需求模型，并通过 Git 同步后端变更。VPS 上的数据库数据仅用于脱敏验证，不提交数据库文件、备份、主机信息、路径以外的运行环境信息、设备随机编号或认证信息。

## 任务

- [ ] 新增 `order_material_requirements` 表及迁移逻辑，包含 `order_id`、`device_id`、`material_id` 外键。
- [ ] 补齐脱敏测试物料主数据，确保每条需求的 `material_id` 都能 JOIN `materials.id`。
- [ ] 将 26B-013 的 25 台设备和 75 条 BOM 需求写入正式表；种子使用固定随机 seed，重复执行幂等。
- [ ] 修改 `/api/v1/orders/material-status`，按 `documentNo` 精确查 `production_orders.order_no`，返回设备维度和物料维度状态。
- [ ] 订单不存在返回 `404 ORDER_NOT_FOUND`，不得返回全量 `materials` 作为伪订单结果。
- [ ] 增加 API 测试：订单命中、订单不存在、三种状态、物料外键完整性、重复种子不重复。
- [ ] 增加数据库迁移/种子测试，禁止测试数据库文件、VPS 标识、真实设备编号和凭据进入仓库。
- [ ] 在物料流转独立分支提交并推送；禁止从 AI 短剧工作区直接推送。

## 验收

```text
POST /api/v1/orders/material-status
{
  "documentNo": "26B-013",
  "documentType": "ORDER_NO"
}
```

必须返回订单 `26B-013`、产品“自动化流水线设备”、25 台设备关联需求和 75 条物料需求；三种状态均需覆盖，所有需求的 `material_id` 必须存在于 `materials`。

## 脱敏与仓库边界

允许进入 Git：迁移脚本、后端源码、单元测试、脱敏架构文档。

禁止进入 Git：SQLite 数据库、SQLite 备份、VPS 地址/主机名、访问凭据、token、随机设备编号、真实运行日志及上传文件。
